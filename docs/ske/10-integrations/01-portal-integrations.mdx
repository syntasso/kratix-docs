Portal integrations publish Promises as catalogue entries and request forms, so developers
can discover and request platform capabilities. Publication and request delivery are separate:
verify both before making an integration available to developers.

## Choose your portal

| Portal | Controller | Publication | Request journey |
| --- | --- | --- | --- |
| [Backstage](/ske/integrations/portal-controller/backstage/intro) | Portal Controller | Documents in Git or bucket storage, discovered by Backstage | Install SKE plugins, configure backend access and permissions, then submit requests |
| [Cortex](/ske/integrations/portal-controller/cortex/intro) | Portal Controller | Entities and workflows through the Cortex API | Configure GitHub or GitLab integration and a GitOps agent to apply requests |
| [Port (Preview)](/ske/integrations/port) | Separate Port Controller | Port entities and actions | Follow the Port guide for Ocean, GitHub Actions and GitOps setup |

The shared Portal Controller supports Backstage and Cortex instances, Promise selection with
labels, and document customisation through `PortalCustomization`.
Start with your portal's guide, including its prerequisites and verification steps.
Use [How the Portal Controller works](/ske/integrations/portal-controller/intro)
to understand the shared publication pipeline.

:::info Port is a Preview feature
Port does not use the shared Portal Controller. Review the
[Preview support policy](/ske/support#preview-features) and discuss production suitability with Syntasso.
:::

## Customise the right layer

- Change the Promise API to change the resource contract and generated form fields.
- Use `PortalCustomization` to change generated documents, optionally with [Portal Patch](/ske/integrations/portal-controller/portal-patch/intro).
- Use the [Backstage plugin APIs](/ske/reference#portal-apis-and-plugins) to change the Backstage interface.

See [Backstage customisation](/ske/integrations/portal-controller/backstage/customising-the-request-template)
or [Cortex customisation](/ske/integrations/portal-controller/cortex/cortex-examples).

## Existing installations

:::info Upgrade from a standalone controller
The standalone Backstage and Cortex Controllers are deprecated. Follow the
[Backstage migration guide](/ske/integrations/portal-controller/backstage/migrating-from-backstage)
or [Cortex migration guide](/ske/integrations/portal-controller/cortex/migrating-from-cortex).
:::

Check [component compatibility](/ske/releases/compatibility) before an upgrade.
For publication failures, use [portal sync troubleshooting](/ske/integrations/portal-controller/troubleshooting).
