## Overview

SKE Lift turns an existing cloud estate, e.g. AWS, Azure, GCP, a Kubernetes-native
estate, or a mix into Kratix Promises and Resource Requests. It finds the
infrastructure patterns that repeat across an account and proposes each one as a
reusable, requestable platform capability.

## What gets installed

`kratix plugin add skelift` installs two CLI plugins:

| Command | What it does |
|---|---|
| `kratix skelift check` | Validates a generated Promise's CRD, workflows, and examples |
| `kratix skelift review` | Fails if a review-findings artifact still has unresolved critical or high findings |

And three agent skills:

| Skill | What it does |
|---|---|
| `cloud-to-kratix-promise` | Discovers a cloud estate, classifies repeated patterns, and drafts Promises |
| `kratix-build-promise` | Builds a Kratix Promise from scratch, including API schema and pipelines |
| `kratix-consume-promise` | Requests resources from a Kratix platform and checks their status |

They are installed to three locations:

| Path | Contents |
|---|---|
| `~/.kratix/plugins/bin` | The CLI plugin binaries |
| `~/.kratix/skills` | The skills, for any agent to use |
| `~/.claude/skills` | A copy of the skills, where Claude Code finds them automatically |

## Prerequisites

- The `kratix` CLI at version `0.19.0` or later. See the
  [Kratix CLI documentation](/main/kratix-cli/intro) for installation.
- An Enterprise Releases token.

:::note
See [SKE tokens](/ske/reference/tokens) for an overview of the different SKE
tokens and which one to use here. SKE Lift needs the Enterprise Releases token,
which begins with `github_pat_`.
:::

## Install

Pipe the token in on stdin to keep it out of your shell history:

```bash
echo "<YOUR_ENTERPRISE_RELEASES_TOKEN>" | kratix plugin add skelift --token-stdin
```

The token can also be passed as a flag, which is more convenient but leaves the
value in your shell history:

```bash
kratix plugin add skelift --token <YOUR_ENTERPRISE_RELEASES_TOKEN>
```

The command reports what it installed and where. Unlike other SKE plugins, you
do not need to download release artifacts or place binaries yourself.

### Add the plugin directory to your PATH

The Kratix CLI finds plugins on your `PATH` and nowhere else, so the install
directory has to be on it. If the command reports that
`~/.kratix/plugins/bin` is not on your `PATH`, add it to your shell profile:

```bash
export PATH="$HOME/.kratix/plugins/bin:$PATH"
```

### Restart your agent

Agents read skills at start-up. Restart Claude Code, or your agent of choice,
before expecting the skills to be available.

## Verify the installation

Confirm the CLI can see both plugins:

```bash
kratix plugin list
```

You should see `kratix skelift check` and `kratix skelift review` listed, with
`~/.kratix/plugins/bin` as their location.

To confirm a plugin runs, request its help:

```bash
kratix skelift review --help
```

You should see output similar to:

```bash
Validate a review-findings artifact and fail if unresolved critical or high findings remain.

Usage:
  review [flags]
```

Confirm the skills are on disk:

```bash
ls ~/.kratix/skills
```

## Updating SKE Lift

Run the install command again. Each run installs the current release and
overwrites whatever is already at those paths, so any local edits to an
installed skill are lost.

```bash
echo "<YOUR_ENTERPRISE_RELEASES_TOKEN>" | kratix plugin add skelift --token-stdin
```

## Using the skills with other agents

Claude Code is configured automatically. For any other agent, point it at
`~/.kratix/skills`, which holds the same skills as plain directories of
Markdown. Consult your agent's documentation for how it discovers skills.
