## Overview

The Portal Controller syncs Kratix Promises and Resource requests into a developer portal, such as Backstage or Cortex, from a single, unified integration. It replaces the
[Backstage Controller](./backstage-controller) and [SKE Cortex Controller](./cortex-controller), which are now deprecated in its favour. See
[Portal Controller](/ske/integrations/portal-controller/intro) for the full documentation.

The release manifest is available at:

```
http://syntasso-enterprise-releases.s3-website.eu-west-2.amazonaws.com/#ske-portal-controller/
```

## Release Notes

### [v0.2.0](http://syntasso-enterprise-releases.s3-website.eu-west-2.amazonaws.com/#ske-portal-controller/v0.2.0/)

#### Features

* Initial release.
* Sync Promises and Resource requests into Backstage or Cortex via a single `SKEIntegration` of `type: portal-controller`.
* Opt a Promise or Resource into a portal with a `kratix.io/portal-<type>` label.
* Backstage portals can own their Destination and state store, or adopt existing ones, via `config.destination` and `config.stateStore`.
* `pull-request` delivery mode for Backstage portals, raising developer requests as pull requests for review before they reach the platform. GitHub only.
* Cortex portals run a setup Job and a status exporter that pushes resource status changes as they happen.
* `PortalCustomization` CRD for customizing generated entities, replacing `BackstageEntityCustomization`.
* Declarative customization with [Portal Patch](/ske/integrations/portal-controller/portal-patch/intro) recipes.
* Bring-your-own portal types via `adapterConfig.image`.
* Migration guides for moving off the standalone Backstage and Cortex Controllers.
