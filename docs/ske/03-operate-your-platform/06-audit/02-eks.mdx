On Amazon EKS, the Kubernetes API server sends its audit log to CloudWatch
Logs. This page shows how to turn the audit log on, where to find it, and how
to count the users of your platform, in CloudWatch Logs Insights or in a
Grafana dashboard.

Each create, update and delete of a resource request carries the
[audit annotation](/ske/operations/audit/requester#audit-log)
`attribution.platform.syntasso.io/last-changed-by`, set to the user who made
the change.

## Turning on the audit log

EKS does not send the audit log anywhere until you turn on the `audit` log type
for your platform cluster. See
[Send control plane logs to CloudWatch Logs](https://docs.aws.amazon.com/eks/latest/userguide/control-plane-logs.html)
in the EKS documentation. For example, with the AWS CLI:

```bash
aws eks update-cluster-config \
  --name <CLUSTER_NAME> \
  --logging '{"clusterLogging":[{"types":["audit"],"enabled":true}]}'
```

The EKS audit policy already records writes to resource requests, so there is
nothing else to set up.

## Finding the logs

EKS writes the audit log to the log group `/aws/eks/<CLUSTER_NAME>/cluster`, in
log streams that start with `kube-apiserver-audit-`. Each line is one audit
event in JSON, and the user is in
`annotations.attribution.platform.syntasso.io/last-changed-by`.

## Setting log retention {#retention}

You can only see activity and count your platform users if their events are
still in the log group. To count the users who used your platform over the last
year, you need to keep a year of logs.

For that, check the log group's retention, and change it if you need to:

```bash
aws logs put-retention-policy \
  --log-group-name /aws/eks/<CLUSTER_NAME>/cluster \
  --retention-in-days 365
```

CloudWatch charges for the logs it stores, so a longer retention will cost more.
Check the [AWS pricing page](https://aws.amazon.com/cloudwatch/pricing/) to find
out the relevant price for your scenario.

## Counting platform users {#unique-users}

With the audit log turned on, you can count platform users in CloudWatch Logs
Insights or in Grafana.

### Using CloudWatch

1. Open [CloudWatch Logs Insights](https://console.aws.amazon.com/cloudwatch/home#logsV2:logs-insights).
1. Select the log group `/aws/eks/<CLUSTER_NAME>/cluster`.
1. Choose the time range to count over.
1. Run this query:

```
filter ispresent(`annotations.attribution.platform.syntasso.io/last-changed-by`)
  and stage = "ResponseComplete"
  and responseStatus.code < 400
  and requestURI not like /dryRun/
| stats count_distinct(`annotations.attribution.platform.syntasso.io/last-changed-by`) as users
```

This `filter` keeps the changes to resource requests that succeeded. It drops
the changes Kubernetes rejected and any dry runs, such as the ones
`kubectl diff` sends, which also carry the audit annotation.

#### Other useful CloudWatch queries

How many changes each user made:

```
filter ispresent(`annotations.attribution.platform.syntasso.io/last-changed-by`)
  and stage = "ResponseComplete"
  and responseStatus.code < 400
  and requestURI not like /dryRun/
| stats count(*) as changes by `annotations.attribution.platform.syntasso.io/last-changed-by` as user
| sort changes desc
```

Who created, updated and deleted a request:

```
filter ispresent(`annotations.attribution.platform.syntasso.io/last-changed-by`)
  and stage = "ResponseComplete"
  and responseStatus.code < 400
  and requestURI not like /dryRun/
  and objectRef.namespace = "<NAMESPACE>"
  and objectRef.name = "<REQUEST_NAME>"
| fields @timestamp, `annotations.attribution.platform.syntasso.io/last-changed-by` as user, verb, objectRef.resource as type
| sort @timestamp desc
```

## Grafana

Grafana can run the same queries through its CloudWatch data source. The
dashboard below shows the number of unique users, the number of changes, the
changes each user made, and the most recent changes. To set it up:

1. Give Grafana access to the log group. See
   [Configure the CloudWatch data source](https://grafana.com/docs/grafana/latest/datasources/aws-cloudwatch/configure/)
   in the Grafana documentation. Grafana needs to run Logs Insights queries on
   `/aws/eks/<CLUSTER_NAME>/cluster`.
1. Add the CloudWatch data source in Grafana.

## Known limitations

- **Counts only go back as far as your [retention](#retention).**
- **The recorded user is only as specific as the way users log in.** If many
  users share one IAM role, the audit log records the role's username for all
  of them, unless you set
  [`userInfoField`](/ske/operations/audit/requester#user-info-field)
  to a field that is different for each user. Run
  `kubectl auth whoami -o yaml` to see which fields your cluster gives you.
  With IAM Identity Center, for example, `extra.sessionName` is often the
  user's username.
- **Some changes have no user.** For example, deletes through GitOps. See
  [What is not recorded](/ske/operations/audit/requester#what-is-not-recorded).
