A `GitStateStore`'s delivery mode controls how Kratix writes to it. By default, Kratix pushes
straight to the branch. With pull request delivery, SKE opens a pull request for each change
instead, and the change reaches the cluster only when someone merges it. SKE never merges the pull
request itself.

Pull request delivery works with GitHub (github.com and GitHub Enterprise Server) and Azure DevOps.

## What you need

<Tabs className="boxedTabs" groupId="gitProvider">
<TabItem value="github" label="GitHub">

- A `GitStateStore` on GitHub, authenticating with a token (`basicAuth`) or a GitHub App
  (`githubApp`). See [GitStateStore authentication](/main/reference/statestore/gitstatestore#auth).
- Read and write access to the repository's **Contents** and **Pull requests** for that token or
  GitHub App.

</TabItem>
<TabItem value="azure" label="Azure DevOps">

- A `GitStateStore` on Azure DevOps, authenticating with a personal access token (`basicAuth`).
- The **Code (Read & write)** scope on that token.
- The **Contribute**, **Create branch** and **Contribute to pull requests** permissions on the
  repository. The project's Contributors group has them by default.

</TabItem>
</Tabs>

:::warning

A Destination with `filepath.mode: aggregatedYAML` cannot use pull request delivery. Kratix refuses
to create or update the Destination or the `GitStateStore` if the change would put them together.

:::

## Turn it on

Add a `delivery` block to the `GitStateStore`:

<Tabs className="boxedTabs" groupId="gitProvider">
<TabItem value="github" label="GitHub">

```yaml
apiVersion: platform.kratix.io/v1alpha1
kind: GitStateStore
metadata:
  name: production
spec:
  url: https://github.com/acme/platform-state
  branch: main
  authMethod: basicAuth
  secretRef:
    name: git-credentials
    namespace: default
  delivery:
    mode: pullRequest
    config:
      provider: github
```

</TabItem>
<TabItem value="azure" label="Azure DevOps">

```yaml
apiVersion: platform.kratix.io/v1alpha1
kind: GitStateStore
metadata:
  name: production
spec:
  url: https://dev.azure.com/acme/platform/_git/platform-state
  branch: main
  authMethod: basicAuth
  secretRef:
    name: git-credentials
    namespace: default
  delivery:
    mode: pullRequest
    config:
      provider: azureDevOps
---
apiVersion: v1
kind: Secret
metadata:
  name: git-credentials
  namespace: default
stringData:
  username: kratix # any value that is not empty
  password: <PERSONAL_ACCESS_TOKEN>
```

</TabItem>
</Tabs>

SKE now writes to every Destination that uses this `GitStateStore` through pull requests. For the
optional settings, see the [pull request delivery reference](/ske/reference/pull-request-delivery).

## Check it works

Request a resource from a Promise scheduled to one of those Destinations. Its `STATUS` links the
pull request:

```bash
kubectl get <RESOURCE_KIND> <RESOURCE_NAME> -n <NAMESPACE>
```

```text
NAME    MESSAGE              STATUS
redis   Redis provisioned    Waiting for approval: https://github.com/acme/platform-state/pull/42
```

Merge the pull request. Within 30 seconds the request is ready and any later pipelines run.

## Review a change

Each change to a request gets its own pull request, opened from a `kratix/<WORKPLACEMENT_NAME>`
branch into the Destination's branch.

- **Merge it** (**Complete** on Azure DevOps) to write the change to the Destination's branch.
- **Close it without merging** (**Abandon** on Azure DevOps) to reject the change. The request
  fails, and its `STATUS` quotes your closing comment. On GitHub, use **Close with comment**. On
  Azure DevOps, comment within a minute of abandoning the pull request, before or after:

  ```text
  NAME    MESSAGE              STATUS
  redis   Redis provisioned    Rejected in https://github.com/acme/platform-state/pull/42: "not during the freeze"
  ```

Anyone who can read the request can read that comment, even without access to the repository.

SKE does not open a pull request for the same files again. A new one opens when the request or
the Promise produces different files, or when you retry.

:::warning Don't change SKE's branches by hand

Do not commit to the `kratix/<WORKPLACEMENT_NAME>` branches or edit SKE's files on the
Destination's branch. SKE replaces those commits, or opens a pull request to undo them. Change the
Promise or the request instead.

:::

## Retry a rejected change

To force SKE to recreate a pull request, for example when the previous one was closed without
being merged, label the request's Work with `kratix.io/redeliver=true`:

```bash
kubectl label works -n <NAMESPACE> \
  -l kratix.io/promise-name=<PROMISE_NAME>,kratix.io/resource-name=<RESOURCE_NAME> \
  kratix.io/redeliver=true
```

## Delete a request

Deleting a request also opens a pull request to remove its files from the State Store. The request
is only removed when that pull request is merged. The request's status shows where it is:

```text
NAME    MESSAGE              STATUS
redis   Redis provisioned    Waiting for approval to remove: https://github.com/acme/platform-state/pull/57
```

If a reviewer closes the removal pull request without merging it, the workloads keep running and
the request stays. To retry, use the label above. To let the request finish deleting and keep its
files, see
[Deleting](/ske/reference/pull-request-delivery#deleting).
