A `GitStateStore`'s delivery mode controls how Kratix writes to the Git
repository. By default, Kratix pushes straight to the branch. With pull request
delivery, SKE opens a pull request for each change instead, and the change
reaches the cluster only after someone merges it. SKE never merges the pull
request itself.

Pull request delivery works with
[GitHub pull requests](https://docs.github.com/en/pull-requests) (github.com
and GitHub Enterprise Server),
[Azure DevOps pull requests](https://learn.microsoft.com/en-us/azure/devops/repos/git/about-pull-requests),
and [GitLab merge requests](https://docs.gitlab.com/user/project/merge_requests/).
GitLab calls a pull request a merge request.

## What you need

<Tabs className="boxedTabs" groupId="gitProvider">
<TabItem value="github" label="GitHub">

- A `GitStateStore` on GitHub, authenticating with a
  [personal access token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)
  (`basicAuth`) or a
  [GitHub App](https://docs.github.com/en/apps/creating-github-apps/about-creating-github-apps/about-creating-github-apps)
  (`githubApp`). See
  [GitStateStore authentication](/main/reference/statestore/gitstatestore#auth).
- Read and write access to the repository's **Contents** and **Pull requests**
  for that token or GitHub App.

</TabItem>
<TabItem value="azure" label="Azure DevOps">

- A `GitStateStore` on Azure DevOps, authenticating with a
  [personal access token](https://learn.microsoft.com/en-us/azure/devops/organizations/accounts/use-personal-access-tokens-to-authenticate)
  (`basicAuth`).
- The **Code (Read & write)** scope on that token.
- The **Contribute**, **Create branch** and **Contribute to pull requests**
  permissions on the repository. The project's Contributors group has them by
  default.

</TabItem>
<TabItem value="gitlab" label="GitLab">

- A `GitStateStore` on GitLab with an `https` URL, authenticating with an
  [access token](https://docs.gitlab.com/security/tokens/) (`basicAuth`).
- The `api` and `write_repository` scopes on that token.
- At least the **Developer** role on the project for the token's user.

Use a
[project access token](https://docs.gitlab.com/user/project/settings/project_access_tokens/)
or a token for a
[service account](https://docs.gitlab.com/user/profile/service_accounts/), so
the token can reach only the projects SKE writes to. A
[personal access token](https://docs.gitlab.com/user/profile/personal_access_tokens/)
also works.

GitLab access tokens expire, after 365 days by default. Replace the `password`
in the Secret before the token expires.

</TabItem>
</Tabs>

:::warning

A Destination with `filepath.mode: aggregatedYAML` cannot use pull request
delivery. Kratix refuses to create or update the Destination or the
`GitStateStore` if the change would put them together.

:::

## Turn it on

Add a `delivery` block to the `GitStateStore`:

<Tabs className="boxedTabs" groupId="gitProvider">
<TabItem value="github" label="GitHub">

```yaml
apiVersion: platform.kratix.io/v1alpha1
kind: GitStateStore
metadata:
  name: production
spec:
  url: https://github.com/acme/platform-state
  branch: main
  authMethod: basicAuth
  secretRef:
    name: git-credentials
    namespace: default
  # highlight-start
  delivery:
    mode: pullRequest
    config:
      provider: github
  # highlight-end
```

</TabItem>
<TabItem value="azure" label="Azure DevOps">

```yaml
apiVersion: platform.kratix.io/v1alpha1
kind: GitStateStore
metadata:
  name: production
spec:
  url: https://dev.azure.com/acme/platform/_git/platform-state
  branch: main
  authMethod: basicAuth
  secretRef:
    name: git-credentials
    namespace: default
  # highlight-start
  delivery:
    mode: pullRequest
    config:
      provider: azureDevOps
  # highlight-end
```

</TabItem>
<TabItem value="gitlab" label="GitLab">

```yaml
apiVersion: platform.kratix.io/v1alpha1
kind: GitStateStore
metadata:
  name: production
spec:
  url: https://gitlab.com/acme/platform-state.git
  branch: main
  authMethod: basicAuth
  secretRef:
    name: git-credentials
    namespace: default
  # highlight-start
  delivery:
    mode: pullRequest
    config:
      provider: gitlab
  # highlight-end
```

</TabItem>
</Tabs>

SKE now writes to every Destination that uses this `GitStateStore` through pull
requests. For the optional settings, see the [pull request delivery
reference](/ske/reference/pull-request-delivery).

## Check it works

Request a resource from a Promise scheduled to one of those Destinations. Its
`STATUS` links the pull request:

```bash

```

## Review a change

Each change to a request gets its own pull request for each Destination and
pipeline, opened from a `kratix/<WORKPLACEMENT_NAME>` branch into the
Destination's branch. Its title starts with `Kratix: deliver` or `Kratix:
remove`.

<Tabs className="boxedTabs" groupId="gitProvider">
<TabItem value="github" label="GitHub">

- **Merge it** to write the change to the Destination's branch.
- **Close it without merging** to reject the change. SKE marks the request as
  rejected, and if the pull request was closed with **Close with comment**, the
  comment is quoted in the `STATUS` of the request:

  ```text
  NAME    MESSAGE              STATUS
  redis   Redis provisioned    Rejected in https://github.com/acme/platform-state/pull/42: "not during the freeze"
  ```

</TabItem>
<TabItem value="azure" label="Azure DevOps">

- **Complete** it to write the change to the Destination's branch.
- **Abandon** it to reject the change. SKE marks the request as rejected, and if
  you comment on the pull request within a minute of abandoning it, before or
  after, the comment is quoted in the `STATUS` of the request:

  ```text
  NAME    MESSAGE              STATUS
  redis   Redis provisioned    Rejected in https://dev.azure.com/acme/platform/_git/platform-state/pullrequest/42: "not during the freeze"
  ```

</TabItem>
<TabItem value="gitlab" label="GitLab">

- **Merge** it to write the change to the Destination's branch.
- **Close merge request** to reject the change. SKE marks the request as
  rejected, and if you comment on the merge request within a minute of closing
  it, before or after, the comment is quoted in the `STATUS` of the request:

  ```text
  NAME    MESSAGE              STATUS
  redis   Redis provisioned    Rejected in https://gitlab.com/acme/platform-state/-/merge_requests/42: "not during the freeze"
  ```

</TabItem>
</Tabs>

SKE does not open a pull request for the same files again. A new one opens when
the request or the Promise produces different files, or when you retry.

:::warning Don't change SKE's branches by hand

Do not commit to the `kratix/<WORKPLACEMENT_NAME>` branches or edit SKE's files
on the Destination's branch. SKE replaces those commits, or opens a pull request
to undo them the next time it writes the request. Change the Promise or the
request instead.

:::

## Retry a rejected change

To force SKE to recreate a pull request, for example when the previous one was
closed without being merged, label the request's Work with
`kratix.io/redeliver=true`:

```bash
kubectl label works -n <NAMESPACE> \
  -l kratix.io/promise-name=<PROMISE_NAME>,kratix.io/resource-name=<RESOURCE_NAME> \
  kratix.io/redeliver=true
```

SKE removes the label once it has acted on it. For what SKE does in each case,
see the [pull request delivery
reference](/ske/reference/pull-request-delivery#how-ske-handles-pull-requests).

## Delete a request

Deleting a request also opens a pull request to remove its files from the State
Store, after the Promise's delete workflow finishes. The request is only removed
when that pull request is merged. The request's status shows the URL of the pull
request:

<Tabs className="boxedTabs" groupId="gitProvider">
<TabItem value="github" label="GitHub">

```text
NAME    MESSAGE              STATUS
redis   Redis provisioned    Waiting for approval to remove: https://github.com/acme/platform-state/pull/57
```

</TabItem>
<TabItem value="azure" label="Azure DevOps">

```text
NAME    MESSAGE              STATUS
redis   Redis provisioned    Waiting for approval to remove: https://dev.azure.com/acme/platform/_git/platform-state/pullrequest/57
```

</TabItem>
<TabItem value="gitlab" label="GitLab">

```text
NAME    MESSAGE              STATUS
redis   Redis provisioned    Waiting for approval to remove: https://gitlab.com/acme/platform-state/-/merge_requests/57
```

</TabItem>
</Tabs>

If a reviewer closes the removal pull request without merging it, the workloads
keep running and the request stays on the platform. To retry by opening a new
pull request, use the label above. To let the request finish deleting and keep
its files, see [Deleting](/ske/reference/pull-request-delivery#deleting).
