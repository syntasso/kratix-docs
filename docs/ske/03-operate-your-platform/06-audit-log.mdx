The SKE Platform Manager adds the person who made each change to a resource
request to the Kubernetes audit log. You can use it to see who created,
updated or deleted a request, or to count the people using your platform.

## Requirements

- SKE Platform Manager `<RELEASE_VERSION>` or later.
- The Kubernetes API server audit log turned on, with a policy that logs
  writes to resource requests at the `Metadata` level or above. The default
  audit policies of managed Kubernetes services, such as AKS, EKS and GKE,
  already do this.

If you run your own API server, a rule like this one logs every write:

```yaml
apiVersion: audit.k8s.io/v1
kind: Policy
rules:
  - level: Metadata
    verbs: ["create", "update", "patch", "delete"]
```

## The audit annotation

Each create, update and delete of a resource request gets the audit
annotation `attribution.platform.syntasso.io/last-changed-by`:

```json
{
  "kind": "Event",
  "verb": "create",
  "user": { "username": "oidc:alice" },
  "objectRef": { "resource": "redis", "namespace": "default", "name": "my-redis", "apiGroup": "marketplace.kratix.io" },
  "annotations": {
    "attribution.platform.syntasso.io/last-changed-by": "alice@example.com"
  }
}
```

Its value depends on who made the change:

| Who made the change | Value |
|---|---|
| A person, for example with `kubectl` | The person's identity, read from [`spec.attribution.userInfoField`](/ske/integrations/portal-controller/reference/audit-and-ownership#user-info-field) |
| A GitOps tool listed in `spec.attribution.requireAnnotationsFrom.serviceAccounts` | The `kratix.io/last-changed-by` annotation the portal set on the request |
| Kratix itself, or a username starting with `system:` or one of [`spec.attribution.skipUsernamePrefixes`](/ske/integrations/portal-controller/reference/audit-and-ownership#skip-username-prefixes) | No annotation |

Kratix's own changes, such as adding finalizers or updating the status, are
never recorded as a person's change.

## Querying the audit log

How you read the audit log depends on where your cluster sends it. For a log
file, this lists who changed which request:

```bash
jq -c 'select(.annotations["attribution.platform.syntasso.io/last-changed-by"])
  | {who: .annotations["attribution.platform.syntasso.io/last-changed-by"], verb, request: .objectRef.name}' audit.log
```

And this counts the people who made changes:

```bash
jq -r '.annotations["attribution.platform.syntasso.io/last-changed-by"] // empty' audit.log | sort -u | wc -l
```

## What is not recorded

- **Deletes through GitOps.** The request's file is removed from git, so
  nothing says who removed it.
- **Changes from a GitOps tool that is not listed** in
  `spec.attribution.requireAnnotationsFrom.serviceAccounts`.
- **Changes made while the SKE Platform Manager is unreachable.** Kubernetes
  still accepts the change, so Kratix keeps working, but the audit event has
  no annotation.
